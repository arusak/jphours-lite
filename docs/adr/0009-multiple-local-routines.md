# Own multiple local Routines in one persisted collection

Keep up to 100 Routines in a separate versioned local-storage collection owned by the existing Routine repository. Store the selected Routine ID and each Routine's last-access time outside Routine content so selection and ordering remain local concerns and portable files retain their existing format. Read current storage before each mutation and publish success only after writing the complete candidate collection; ID-aware saves update existing records without selecting them or inserting deleted records.

Migrate supported single-Routine data when the collection key is absent, preserving the legacy key as a backup. Once present, the collection is authoritative. Reject corrupt, unsupported, duplicate-ID, or over-capacity collections without overwriting their raw bytes; startup blocks the editor and offers Retry. A missing selected ID can be repaired by choosing the most recently accessed Routine. Keep pending edits after failed saves and flush them before selection, creation, import, deletion, Session start, or PWA update acceptance.

Record access on startup restoration, explicit opening, creation, confirmed import, and selection of a replacement after deleting the selected Routine. Edits, exports, Session settings saves, drawer opening, returning from a Session, and opening the already selected row do not record access. Sort copies by descending access time, retaining stored array order for ties. Deleting the last Routine creates a default Practice routine. New routine names use the first available normalized exact name, starting with New routine and then New routine 2; other duplicate names remain allowed.

Confirmed import adds and opens a Routine with fresh local identities. It supersedes the replacement behavior described in [ADR 0005](0005-routine-storage-and-file-compatibility.md), while preserving strict file validation and preview. Creation and import both enforce the cap at the repository boundary; storage quota can fail before that count. A Session captures its source Routine ID, and saved settings update only that source without changing selection or access order. No cloud synchronization, Session restoration, or coordination of simultaneous browser-tab edits is introduced.
